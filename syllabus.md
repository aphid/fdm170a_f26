## Course Overview

### Course Catalog Description
Introduction to the conceptual and technical fundamentals of making digital media. Covers principles of digital image manipulation, basic web authoring, and interface design through projects that introduce production techniques and methods.

### Approach
This course takes the approach that digital art can be a means to remake and rethink cinema. We are going to think about how film editing can be practiced by coding, how the web provides an excellent medium for composing multiscreen films, and how we can use programming to make interactive, database films. 

The outstanding question of digital media is: **how can we translate the language of art (film and other arts)—issues of composition, interpretation, editing, montage, and narrative—into the language of code and vice versa?** 

We will pay attention to the art and media histories of video and film and examine how ideas and theories of montage and editing of images, especially moving images, can be written as code. Projects will be created for the web with HTML, CSS, and JavaScript. By the end of the course, you will be making simple, interactive videos and have the conceptual and technical tools to embark on making sophisticated, interactive videos.

*This version of FDM 170A was co-developed by [Warren Sack](https://people.ucsc.edu/~wsack/) and [Abram Stern](https://creative.ucsc.edu/people/faculty/#abram-stern).*

## Requirements

There are eight required projects for this course. Seven are defined assignments, and for the eighth and final project, you will pick one of the earlier seven projects to produce a second version.

### Summary of Assigned Projects
1. **Re-sequencing:** Gather at least twenty of Eadweard Muybridge’s pre-cinematic images to re-sequence and compose them into a story on a webpage.
2. **Collage and Concrete Poetry:** Reproduce an existing concrete poem using CSS/HTML, or format a standard poem into a concrete poem.
3. **Montage:** Re-edit clips from Sergei Eisenstein’s *Battleship Potemkin* (1925) using JSON and JavaScript.
4. **Instructions for Drawings:** Execute one of artist Sol LeWitt’s wall drawings by hand and with JavaScript code.
5. **Multi-Screen Interactive:** Create a nine-screen interactive web composition using HTML, CSS, and JavaScript.
6. **{Narrative} Structures:** Write a story grammar using artificial intelligence planning operators expressed in JSON to generate story variants.
7. **Database Cinema:** Assemble and annotate a video clip database using JSON, then repurpose your story grammar to automatically generate narrative montages.
8. **Repeat:** Reiterate one of the previous seven projects.

### Grading Components & Workload
For each project, there are two graded deliverables:
1. The completed technical project.
2. A one-paragraph critique written for every member of your assigned working group.

Classes are divided into working groups of four students. You are responsible for posting critiques in response to three peers across all eight assignments. We estimate project work will take between 10 to 12 hours per assignment.

### What is Critique?
Critique is an essential part of arts education. We distinguish between two types:
* **Negative Critique:** Complaints or arguments directed against the work or artist.
* **Positive Critique:** Advocacy focusing on understanding the artist's intent and providing constructive feedback.

> **Key Rule for Critiques:** Focus strictly on what you can see, experience, and describe. Avoid expressing personal like/dislike ("I like this") or using first-person pronouns (*I, me, my, myself*). Instead, describe what the artwork achieves and use constructive phrasing such as: *"The artwork could be strengthened in the following ways..."*

### Provided Assignment Resources
For each project, six core resources are provided on the course site:
1. **Introductory Video & Script:** 10–30 minute historical/theoretical background videos and companion PDF scripts.
2. **Readings & Screenings:** PDF readings and assigned film/web artwork viewings.
3. **Project Description:** Extended criteria and posting instructions.
4. **Code Talkthrough:** Interactive online code narration allowing you to modify and run code directly in the browser.
5. **CodePen Starter Code:** Pre-formatted base code ready for you to fork and edit.
6. **Critique Prompts:** Discussion prompts guiding peer review criteria.

## Course Policies & Campus Resources

### Problem Solving, Troubleshooting, and AI
AI tools can serve as productivity aids, but relying on them prematurely can hinder learning. When encountering bugs, follow these steps:
1. **Search Exact Error Messages:** Wrap error text in quotes (excluding line numbers or specific variable names).
2. **Read Official Documentation:** Check [MDN Web Docs](https://developer.mozilla.org/en-US/) first, followed by W3Schools.
3. **Ask for Help:** Post your issue on the course Matrix/Element chatroom with code snippets and descriptions.
4. **Code Attribution:** Reusing public code solutions (e.g., StackOverflow) is permitted. However, code is governed by CC BY-SA 4.0; you must include a comment providing source attribution.
